# aql-scoreboard

AQL の2チーム戦の正誤を出題者が入力し、参加者が得点状況（得点・リーチ・封鎖）を閲覧するアプリ。複数の部屋で同時に進む試合を、試合IDで分けて扱う。

- 試合ID入力: `/`（試合IDを入れると閲覧画面へ。どの試合があるかは見せない）
- 閲覧: `/<試合ID>`（認証なし。1.5秒ごとに自動更新。リロード不要）
- 入力: `/input/<試合ID>`（試合ごとの入力用パスワードでログイン）
- 管理者: `/admin`（`ADMIN_PASSWORD` でログイン。試合の作成・一覧・削除）
- ルール: `../aql-principles-and-practices/rules/game-rules.md` に従う（ロジックは `game.py`）

本番（aql-sokuhou と同居）では先頭に `/score` が付く（例: `https://aql-sokuhou.q-koken.com/score/503-1`）。画面は相対パスで書いてあるので、前に付くパスを問わず動く。

## ローカル実行

```bash
uv sync
ADMIN_PASSWORD=admin-demo uv run uvicorn app:app --port 8000
# 管理者 http://localhost:8000/admin で試合を作り、閲覧 http://localhost:8000/<ID>・入力 http://localhost:8000/input/<ID>
uv run pytest
```

## 環境変数

| 変数 | 既定 | 説明 |
|---|---|---|
| `ADMIN_PASSWORD` | なし | 管理者パスワード。未設定なら管理者画面は使えない |
| `SECRET_KEY` | なし | ログイン状態（Cookie）の署名鍵。未設定なら初回に乱数で作って DB に保存する |
| `DB_PATH` | `data/scoreboard.db` | SQLite ファイル。再起動後も試合の状態が残る |
| `MAX_QUESTIONS` | `40` | 規定問題数 |

## 試合の作成とログイン

- 管理者画面で「試合ID」「入力用パスワード」「試合名（任意）」を入れて作成する
  - 試合IDは半角英数字と `-` `_` で1〜32文字。英字は小文字にそろえる。`admin` `input` `static` `api` と、すでにあるIDは使えない
  - パスワードは4〜64文字。塩付きのハッシュ（scrypt）だけを保存するので、作成後に確かめることはできない。忘れたら試合を削除して作り直す
- 一覧には試合ID・試合名・対戦と得点・問題数・状況・作成日時と、閲覧・入力画面へのリンクが出る（5秒ごとに更新）。削除は確認ダイアログを経て、その試合の得点・記録・設定をすべて消す
- 入力画面は試合ごとにログインする。ログイン状態は署名付きの Cookie（HttpOnly、24時間有効）で、別の試合には使えない。試合を削除・作り直すと古いログインは無効になる。入力画面の一番下に試合IDと「ログアウト」がある
- パスワードを5回続けて間違えると、30秒受け付けない（試合ごと・管理者ごと）
- 閲覧画面・入力画面で試合が見つからないとき（削除されたときを含む）は「試合が見つかりません」を出す
- 試合を選んだ後の操作は、以下のとおり試合ごとに独立している（取り消し・リセット・閲覧画面に表示する項目も試合ごと）

## 操作

- ○/×: その枠の正解・誤答。誤答で相手チームの封鎖枠は ×1 に戻る
- リーチ・封鎖は文字を出さず、枠の見た目で示す（全画面共通）。リーチ=黄の塗り＋太い枠線、封鎖=斜線。試合終了後はリーチを出さない
- スルー: 正解者なしで次の問題へ（問題数だけ進む）
- 1つ取り消す: 直前の操作を取り消す（何回でも可）
- 参加者名を編集: 1枠2名まで、1人あたり全角6文字（半角12文字）まで。枠に入りきらない名前は横方向に縮めて表示。チームごとに保存
- 空席（練習・ハンデ戦用）: 「参加者名を編集」の各枠の「空席」にチェックを入れて保存すると、その枠は選手が座らない枠になる（既定はチェックなし。チームごとに任意の枠を指定でき、全枠を空席にはできない）。空席の得点は1のまま固定で、○×を受け付けず、リーチ・封鎖にもならない。画面では枠番と点線の空の枠だけを描く。全枠封鎖の判定は空席以外の枠で行う。変更できるのは試合開始前（問題数0、リセット直後）だけで、試合中はチェックボックスが無効になる。リセットでは残り、「1つ取り消す」で戻る。試合記録の各枠に `vacant` が入る
- 閲覧画面に表示する項目: 「問題数」「判定の記録」を個別に ON/OFF（フェアプレー規程で問題番号を出さない場合用）。既定はどちらも OFF（表示しない）。OFF の項目は閲覧用 API の応答からも外れる。取り消し・リセットの対象外
- 試合名・チーム名を変更: 試合名（最大40文字、例「503会議室 第2試合」）は閲覧画面・入力画面の左上とタブ名に出る。空欄なら既定の「AQL 得点状況」（閲覧）／「AQL 正誤入力」（入力）
- オプションルール → 勝利点を変更する: チームごとに勝利点（2〜99999）を設定。ON の間は得点を「現在点/勝利点」で表示し、リーチ・勝敗もそれぞれの勝利点で判定。試合途中でも変更できるが、現在の得点（頭打ち前の積）以下の値は拒否。OFF に戻すのは両チーム200にするのと同じ扱い。「1つ取り消す」で戻り、リセットでは残る
- オプションルール → 40問で終了しない: 無効になった問題に備え、規定問題数を終えても試合を終えない（勝敗は勝利点到達・全枠封鎖のみ）。ON の間、問題数は「第n問」と表示。既定は OFF。「1つ取り消す」で戻り、リセットでは残る。規定問題数を超えてから OFF にすると、その時点で規定問題数による終了になる
- 記録をダウンロード（入力画面の「画像をコピー」の左隣）: `/input/<試合ID>/api/export` から JSON（`aql_record_<試合ID>_YYYYMMDD_HHMMSS.json`）を保存。試合ID・試合名・ルール（規定問題数・勝利点）・問題数・勝敗・両チームの盤面（枠ごとの選手名・得点・×・封鎖・リーチ）・試合開始（最後のリセット）からの全判定を含む。判定には判定時刻（日本時間）と判定後の両チームの得点が付く。取り消した判定は含まれない。選手名は書き出し時点の振り分け
- 試合をリセット: 試合名・チーム名・参加者名・空席・勝利点の設定を残して最初から。確認画面で「試合記録をダウンロードしてリセット」「ダウンロードせずにリセット」「キャンセル」を選ぶ。ダウンロードしてリセットは記録の保存が終わってからリセットし、記録を取得できなければリセットしない
- 表示モード: ライト／ダーク／SportsManiax を端末ごとに選ぶ（閲覧画面の右上の「☰」メニュー、入力画面の「この端末の入力画面」）。閲覧・入力で共通、localStorage に保存、未設定なら OS のライト／ダークに従う。SportsManiax は `~/SportsManiaxDataAnalysis/templates` のレポートのトンマナ（黒地・角なし・赤の見出し・水色／黄の強調・BIZ UDPゴシック＋Saira Extra Condensed）
- QRコードを表示（閲覧画面の右上の「☰」メニューの一番下）: その閲覧画面の URL（クエリ・# は除く）を QR コードにして大きく表示する。URL も文字で出す。「閉じる」・枠の外・Esc で閉じる。QR コードは同梱の `static/vendor/qrcode-generator-2.0.4.js`（MIT、npm の sha512 を照合済み）でブラウザ内で作る
- 表示画面QRコード（入力画面の「記録をダウンロード」の左隣）: その試合の閲覧画面（`/input/<試合ID>` に対する `/<試合ID>`）の QR コードを、閲覧画面の「QRコードを表示」と同じダイアログで出す。部屋の参加者に閲覧画面を案内するときに使う
- 入力画面は幅600px以下で自動的に詰めた表示になり、両チームの○×と「スルー」「1つ取り消す」が1画面に収まる
- 入力画面の設定欄（参加者名・試合名とチーム名・オプションルール・閲覧画面に表示する項目・この端末の入力画面）は畳める。初期は畳んだ状態で、見出しの右に今の設定を表示。開閉の状態は端末ごとに保存
- 並び順: 「チームの左右を入れ替え」「チームごとに枠を5→1」を端末ごとに設定（閲覧画面の右上の「☰」メニュー、入力画面の「この端末の入力画面」）。席の物理配置に合わせるためのもの。閲覧画面と入力画面で別々に保存し、互いに反映しない。並べ替えても枠番と入力先は本来の枠のまま
- 画像をコピー（閲覧画面の右上の「☰」メニュー、入力画面の「試合をリセット」の左隣）: 表示中の得点状況（見出し・勝敗・両チーム。判定の記録は含めない）を PNG にしてクリップボードへ。画像の右下に撮影日時を入れる。入力画面でも閲覧画面と同じ範囲を写し（「非表示中」の問題数も含む）、○×ボタンと「出題者用」の印は写さない。コピーできない環境では PNG を保存する。画像化は同梱の `static/vendor/html-to-image-1.11.13.js`（MIT、npm の sha512 を照合済み）で、すべてブラウザ内で処理する

## デプロイ

```bash
docker build -t aql-scoreboard .
docker run -d -p 80:8000 -e ADMIN_PASSWORD=<管理者パスワード> -v aql-data:/data aql-scoreboard
```

SQLite を使うため、永続ディスクのあるホスト（VM・コンテナ＋ボリューム）で1台だけ動かす。

1試合版（`INPUT_PATH` を使っていた版）の DB をそのまま使うと、起動時に古い `states` / `settings` テーブルを `legacy_states` / `legacy_settings` に名前を変えて残す（新しい版では読まない）。

閲覧画面の QR コード PDF は、試合ごとの URL を渡して作る:

```bash
uv run --no-project --with reportlab python tools/make_qr_pdf.py https://aql-sokuhou.q-koken.com/score/503-1 print/score_503-1.pdf "503会議室 第1試合"
```
